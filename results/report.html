3. Analysis & System Architecture Trade-offs

  • 3.1 Operational Volatility of Free & Cheap Endpoints

    Free public endpoints (nemotron-3-ultra and north-mini-code) showed severe operational instability, meaning many test failures came from infrastructure drops rather than core model limitations:

    • Timeouts & Empty Payloads: High tenant load caused frequent request drops, surfacing as Python NoneType errors (scored as failures per benchmark rules).
    • Queueing Delays: nemotron-3-ultra latencies spiked (p50 > 90s, p95 > 160s) due to API queueing rather than slow raw inference.
    • Takeaway: Free API tiers bring high availability risk and unpredictable latency, making them unfit for production environments.

  • 3.2 Analysis of Symbolic & Reasoning Failures

    Reviewing model output errors highlights key execution and architectural bottlenecks:

    • Order-of-Operations Bias: On math prompts like 6 + 12 / 3 * 2, local models evaluated strictly left-to-right (returning 20 instead of 14), showing how standard attention mechanisms miss operator precedence without step-by-step scratchpads.
    • Host Memory Allocation Crashes: llama-server failed on Item #math_01 due to CUDA host buffer memory spikes during local execution.
    • Output Suppression: north-mini-code often returned single periods (.) at temperature 0.0 when constrained to strict output formats.

  • 3.3 Cost Projections & Production Choice

    Balancing throughput stability and costs guides our final setup:

    • Break-Even Analysis: At 5,000 requests/day, lightweight paid APIs cost < $0.10/day, while cloud GPU instances for local hosting (e.g., AWS g4dn.xlarge) run ~$12.60/day. Self-hosting only becomes cheaper than pay-as-you-go APIs above 85,000 requests/day.
    • Final Recommendation: Use a lightweight paid API (e.g., Claude Haiku or GPT-4o-mini) for low-latency tasks. nemotron-3-ultra is too slow (90s+), and local qwen2.5 needs fine-tuning or scratchpads to fix math errors.
    • Decision Triggers:
      • Switch to local qwen2.5 if volume exceeds 85,000 reqs/day or strict data privacy rules apply.
      • Switch to top-tier paid APIs if task complexity requires >90% symbolic accuracy.
